# Execution plans

For substantial changes, create a plan in `active/` with the problem, acceptance
criteria, design decisions, work steps, verification commands, and unresolved issues.
Update it as evidence changes. Move it to `completed/` after acceptance checks pass.
Use a short task note for small edits.

- [Initial scaffold](completed/initial-scaffold.md): implementation and validation record.
- [Technical debt](tech-debt-tracker.md): work left outside the accepted initial slice.

- [Livepeer backend](completed/livepeer-backend.md): embedded engine integration and verification record.

- [Multi-user accounting](completed/multi-user-accounting.md): implementation and acceptance.

- [Public deployment](completed/public-deployment.md): standalone Compose, package naming and publication.
